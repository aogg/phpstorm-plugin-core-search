# 左侧搜索结果性能优化流程

## 通用优化模式

适用于其他搜索功能的优化可以借鉴以下模式：

- **预过滤**：在收集结果前进行初步筛选
- **分批处理**：避免一次性处理大量数据
- **增量显示**：实时反馈搜索进度
- **内存控制**：使用迭代器和批次限制
- **类型检查**：通过启发式和类型推断过滤无关结果

## 性能优化措施

### 1. 分批处理机制
- **方法级分批**：每批处理3个方法
- **引用级分批**：每批处理20个引用，避免内存爆炸
- **进度显示**：实时更新搜索进度

### 2. 增量显示策略
- 每5秒或累积10个结果时立即显示
- 避免长时间等待，提升用户体验
- 支持取消操作和UI响应

### 3. 内存管理
- 使用迭代器分批获取引用
- 避免一次性加载所有搜索结果
- 批次间短暂休眠让出控制权

## 技术实现要点

### 1. PSI数据访问安全
- 使用 `ApplicationManager.getApplication().runReadAction` 包装所有PSI操作
- 确保PSI访问在读线程中进行，避免UI冻结
- 引用级分批也独立使用 `runReadAction`，避免长时间阻塞

### 2. 异步任务处理
- 使用 `ProgressManager.getInstance().run(Task.Backgroundable)` 实现异步执行
- 支持进度指示和取消操作
- 批次间使用 `Thread.sleep(10)` 让出控制权，让UI线程响应

### 3. 官方组件集成
- 使用 `GlobalSearchScope.projectScope()` 定义搜索范围
- 使用 `ReferencesSearch.search()` 进行引用搜索
- 使用 `UsageViewManager` 和自定义UI组件展示结果

### 4. 引用搜索分批策略
- 查找单个方法调用时不一次性获取所有引用
- 使用迭代器模式：`RefSearch.search().iterator()`
- 每批处理20个引用，避免内存占用过高
- 每个引用批次独立使用 `runReadAction`，减少UI阻塞时间

## 效果验证

通过日志可以看到，原本543个原始结果，经过过滤后显著减少了无效调用，大大提升了搜索结果的相关性和性能。
