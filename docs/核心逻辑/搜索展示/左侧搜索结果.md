# 自动发现三级选项搜索结果显示逻辑

## 案例分析

### 正面案例（显示搜索结果）

**场景1：类中有匹配的public方法且有相关调用**
```
配置规则：["get*"]
当前PHP类：
class User {
    public function getName() { return $this->name; }
    public function getAge() { return $this->age; }
    public function setName($name) { $this->name = $name; }
}

// 在其他地方的调用：
$user = new User();
$name = $user->getName();  // 调用匹配的方法
$age = $user->getAge();    // 调用匹配的方法
```
显示结果：搜索结果会显示 getName() 和 getAge() 方法的调用位置
原因：
1. 类中有public方法getName()和getAge()匹配"get*"规则
2. 这些方法在项目中有引用（usages）
3. 引用经过过滤，保留了相关的调用

**场景2：子类调用父类方法**
```
配置规则：["save*"]
父类：
class BaseRepository {
    public function save($entity) { /* 保存逻辑 */ }
}

子类：
class UserRepository extends BaseRepository {
    public function saveUser($user) {
        $this->save($user);  // 调用父类方法
    }
}
```
显示结果：搜索结果会显示UserRepository中对save()方法的调用
原因：
1. BaseRepository中有public方法save()匹配"save*"规则
2. UserRepository继承自BaseRepository
3. UserRepository中调用了$this->save()，被认为是相关调用

**场景3：静态方法调用**
```
配置规则：["create*"]
当前PHP类：
class UserFactory {
    public static function createUser($data) {
        return new User($data);
    }
    public static function createAdmin($data) {
        return new Admin($data);
    }
}

// 调用：
$user = UserFactory::createUser($data);  // 静态调用
```
显示结果：搜索结果会显示静态调用createUser的位置
原因：静态调用被识别为对UserFactory类方法的有效调用

**场景4：对象方法调用**
```
配置规则：["handle*"]
当前PHP类：
class EventHandler {
    public function handleLogin($user) { /* 处理登录 */ }
    public function handleLogout($user) { /* 处理登出 */ }
}

// 调用：
$handler = new EventHandler();
$handler->handleLogin($user);   // 对象调用
$handler->handleLogout($user);  // 对象调用
```
显示结果：搜索结果会显示两个handle方法的调用位置
原因：对象方法调用被正确识别和过滤

### 反面案例（不显示搜索结果）

**场景1：类中有匹配方法但无任何调用**
```
配置规则：["get*"]
当前PHP类：
class UnusedClass {
    public function getName() { return "test"; }
    public function getAge() { return 25; }
}

// 项目中没有任何地方调用这些方法
```
显示结果：显示"未找到调用匹配 get* 的方法的位置"
原因：虽然类中有匹配的public方法，但这些方法在整个项目中没有任何引用

**场景2：有调用但调用方不是当前类或其子类**
```
配置规则：["process*"]
类A：
class DataProcessor {
    public function processData($data) { /* 处理逻辑 */ }
}

类B（不相关的类）：
class ApiController {
    public function handleRequest() {
        $processor = new DataProcessor();
        $processor->processData($this->data);  // 调用了processData
    }
}
```
显示结果：不显示搜索结果（被过滤掉）
原因：虽然processData方法有调用，但调用方ApiController与DataProcessor无关，过滤时被排除

**场景3：private/protected方法不参与匹配**
```
配置规则：["get*"]
当前PHP类：
class User {
    private function getSecretKey() { return $this->key; }
    protected function getInternalId() { return $this->id; }
    public function getName() { return $this->name; }
}

// 即使有调用private方法的代码，搜索结果也不会显示
```
显示结果：不显示getSecretKey和getInternalId的调用，只显示getName的调用
原因：自动发现只匹配public方法，private/protected方法不参与规则匹配

**场景4：方法名匹配但PSI解析异常**
```
配置规则：["get*"]
当前PHP类：
class User {
    public function getName() { return $this->name; }
}

// 某个调用位置的代码有语法错误或PSI解析失败
$user->getName();  // 这行代码由于某种原因PSI解析失败
```
显示结果：可能不显示该异常调用位置的结果
原因：PSI解析异常导致无法正确识别方法调用，过滤时被跳过

**场景5：调用被注释或在字符串中**
```
配置规则：["get*"]
当前PHP类：
class User {
    public function getName() { return $this->name; }
}

// 调用被注释：
// $user->getName();

// 或在字符串中：
$sql = "$user->getName()";
```
显示结果：不显示这些调用
原因：注释和字符串中的代码不被识别为有效的PSI元素

## 显示逻辑总结

### 核心显示条件
搜索结果显示需要同时满足以下所有条件：

1. **规则匹配**：当前PHP类中至少存在一个public方法，其方法名匹配点击的三级选项规则
2. **方法存在**：能够成功解析到匹配的方法对象（PSI正常工作）
3. **有引用**：匹配的方法在项目范围内有至少一个有效的引用（usage）
4. **调用相关**：至少存在一个调用，其调用方类与当前类相同或为当前类的子类
5. **PSI正常**：所有涉及的PSI元素都能正常解析，无异常情况

### 过滤逻辑
搜索到原始usages后，会进行二次过滤，只保留：

1. **类相关调用**：调用方为当前类或其子类的方法调用
2. **静态调用**：通过类名直接调用的静态方法
3. **对象调用**：通过对象实例调用的方法
4. **排除无关调用**：过滤掉其他不相关类的调用

### 显示方式
根据可用的UI组件按优先级回退：

1. **工具窗口**（首选）：显示完整的搜索结果，包括：
   - 左侧树形结构：按目标方法名分组显示调用位置
   - 右侧预览区域：显示选中方法的源码
   - 双击可跳转到代码位置

2. **自定义弹窗**（备选）：类似工具窗口的功能但以弹窗形式显示

3. **标准用法视图**（最后回退）：使用IDE内置的UsageView显示结果

### 异常处理
- PSI解析异常时会记录日志但不影响其他结果
- UI组件异常时自动回退到更简单的显示方式
- 正则匹配异常时跳过该方法，继续处理其他方法

### 性能考虑
- 只在当前类内搜索匹配的方法，不进行跨类扫描
- 使用项目范围搜索查找usages，但有过滤机制避免显示过多无关结果
- 支持取消操作，响应用户中断
