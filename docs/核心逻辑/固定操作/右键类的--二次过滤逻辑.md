# 固定搜索-对象方法调用：二次过滤逻辑

## 过滤流程

### 第一次过滤（粗筛）
在 `FixedSearchObjectMethodAction.processMethodReferencesWithBatching` 方法中：
- 通过 `PsiTreeUtil.getParentOfType(element, MethodReference::class.java, false)` 获取方法引用
- 只有真正的方法引用才会被收集到批次中

### 第二次过滤（精确过滤）
在 `SearchFilterHelper.filterRelatedObjectUsages` 方法中进行精确过滤：

#### 过滤条件1：对象调用检查
```kotlin
val classReference = methodRef.classReference
if (classReference != null) {
    val className = classReference.text
    if (className.isNotEmpty() && className.startsWith("$")) {
        // 是对象调用，继续检查
    } else {
        // 静态调用（通过类名），跳过
    }
}
```

## 实例类型验证逻辑

### 主要策略：IntelliJ 平台内置类型推断
- **核心方法**：直接使用 `classReference.getType()` 获取变量的推断类型
- **优势**：
  - 利用平台级的类型分析引擎
  - 自动处理数据流分析、控制流分析等复杂情况
  - 与 IDE 的类型检查保持一致
  - 无需手动实现复杂的类型推断逻辑

### 过滤策略：直接忽略不符合条件的对象
- **忽略条件**：
  - `getType()` 失败或返回 null 时
  - 对象不是当前右键类的实例时
- **处理方式**：直接忽略这些对象调用，只记录详细日志用于调试
- **优势**：避免误匹配，提高搜索结果的准确性

### 类型检查实现
```kotlin
fun isTargetClassInstance(classReference: PhpExpression, targetClass: PhpClass): Boolean {
    val targetClassFqn = targetClass.fqn ?: return false

    try {
        // 使用 IntelliJ 平台的内置类型推断
        val inferredType = classReference.getType()
        if (inferredType != null) {
            // 检查推断类型是否包含目标类
            val isTargetType = inferredType.toString().contains(targetClassFqn)
            if (isTargetType) {
                return true
            } else {
                // 不是目标类的实例，直接忽略，记录日志
                ProjectLogHelper.log(
                    targetClass.project,
                    "$searchTypeName: 忽略非目标类实例调用 inferredType=${inferredType}, targetClass=${targetClass.fqn}"
                )
                return false
            }
        } else {
            // 类型推断返回null，直接忽略，记录日志
            ProjectLogHelper.log(
                targetClass.project,
                "$searchTypeName: 类型推断返回null，忽略此调用 classReference=${classReference.text}"
            )
            return false
        }
    } catch (e: Exception) {
        // 类型推断失败，直接忽略，记录日志
        ProjectLogHelper.log(
            targetClass.project,
            "$searchTypeName: 类型推断失败，忽略此调用，错误: ${e.message}, classReference=${classReference.text}"
        )
        return false
    }
}
```

## 过滤结果处理

### ✅ 保留：通过所有检查的对象方法调用
- 变量的可能类型与目标类匹配
- 包括直接赋值、间接赋值等多种情况

### ❌ 跳过：不符合条件的情况
- **静态方法调用**：`ClassName::method()` 形式的调用
- **非目标类实例**：调用对象不是目标类的实例
- **无效引用**：无法解析的引用或类型不匹配

## 类型推断能力

### IntelliJ 平台提供的类型推断
- **数据流分析**：自动跟踪变量在不同代码路径中的类型变化
- **控制流分析**：考虑条件分支、循环等对类型的影响
- **交叉引用解析**：自动解析方法调用、属性访问等的返回类型
- **泛型支持**：处理模板类型和类型参数
- **上下文感知**：基于代码上下文提供准确的类型信息

### 后备机制
- **启发式匹配**：变量名与类名的简单匹配
- **错误处理**：类型推断失败时的优雅降级
- **日志记录**：记录类型推断过程便于调试

## 性能优化

### 分批处理
- **方法级分批**：每批处理3个方法，避免内存压力
- **引用级分批**：每批处理20个引用，控制内存占用
- **增量显示**：每5秒或累积10个结果时更新UI

### 缓存机制
- 编译后的正则表达式缓存
- 类型解析结果缓存（通过 PhpIndex）

这个增强的二次过滤逻辑能够更准确地识别目标类的对象方法调用，大大提高了搜索结果的相关性和准确性。
