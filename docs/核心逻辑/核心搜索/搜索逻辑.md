# 核心搜索二级菜单的点击搜索规则

## 搜索规则总结

点击@core二级菜单中的关键词标签后，后台执行以下搜索逻辑：

1. **方法收集**：查找包含该关键词的所有方法（先从当前类及其父类开始）
2. **全量补充**：如果当前类/父类未找到，则全项目范围查找包含该关键词的方法
3. **引用搜索**：对每个方法搜索其调用位置
4. **二次过滤**：只保留与当前类相关的调用（对象类型或静态调用类为当前类或其子类）
5. **结果展示**：在"查找工具窗口"中显示所有符合条件的调用位置

## 正面案例

### 案例1：当前类方法调用搜索
```php
<?php
class UserService {
    /**
     * 用户登录
     * @core login
     */
    public function login($username, $password) {
        // 登录逻辑
    }
}

class UserController {
    public function handleLogin() {
        $service = new UserService();
        $service->login('user', 'pass'); // <- 会被找到
    }
}
```

**搜索结果**：
- 显示位置：`UserController::handleLogin` 中的 `$service->login('user', 'pass');`

**说明**：对象`$service`的类型为`UserService`，与当前搜索的类匹配。

### 案例2：继承链方法调用搜索
```php
<?php
class BaseService {
    /**
     * 基础操作
     * @core base
     */
    public function baseOperation() {
        // 基础操作
    }
}

class UserService extends BaseService {
    // 继承了 baseOperation 方法
}

class UserController {
    public function handleBase() {
        $service = new UserService();
        $service->baseOperation(); // <- 会被找到
    }
}
```

**搜索结果**：
- 显示位置：`UserController::handleBase` 中的 `$service->baseOperation();`

**说明**：虽然`baseOperation`方法定义在父类中，但子类`UserService`的对象调用也会被匹配。

### 案例3：静态方法调用搜索
```php
<?php
class UserService {
    /**
     * 用户验证
     * @core validate
     */
    public static function validateUser($userId) {
        // 验证逻辑
    }
}

class UserController {
    public function checkUser() {
        UserService::validateUser(123); // <- 会被找到
    }
}
```

**搜索结果**：
- 显示位置：`UserController::checkUser` 中的 `UserService::validateUser(123);`

**说明**：静态调用时，调用类名与当前搜索的类匹配。

### 案例4：子类对象调用搜索
```php
<?php
class BaseService {
    /**
     * 基础方法
     * @core base
     */
    public function baseMethod() {
        // 基础逻辑
    }
}

class AdminService extends BaseService {
    // 继承了 baseMethod 方法
}

class Controller {
    public function handleAdmin() {
        $service = new AdminService();
        $service->baseMethod(); // <- 会被找到
    }

    public function handleBase() {
        $service = new BaseService();
        $service->baseMethod(); // <- 不会被找到（调用者是父类对象）
    }
}
```

**搜索结果**（在AdminService类上搜索@base）：
- 显示位置：`Controller::handleAdmin` 中的 `$service->baseMethod();`
- 不显示：`Controller::handleBase` 中的调用（因为对象类型是BaseService，不是AdminService的子类）

**说明**：当在子类上搜索父类方法时，只匹配子类对象或子类子类的调用。

## 反面案例

### 案例1：无关对象类型的调用
```php
<?php
class UserService {
    /**
     * 用户登录
     * @core login
     */
    public function login($username, $password) {
        // 登录逻辑
    }
}

class OrderService {
    /**
     * 订单登录
     * @core login
     */
    public function login($orderId) {
        // 订单逻辑
    }
}

class Controller {
    public function handle() {
        $userService = new UserService();
        $orderService = new OrderService();

        $userService->login('user', 'pass');   // <- 会被找到
        $orderService->login(123);             // <- 不会被找到（类型不匹配）
    }
}
```

**搜索结果**（在UserService类上搜索@login）：
- 显示位置：`Controller::handle` 中的 `$userService->login('user', 'pass');`
- 不显示：`Controller::handle` 中的 `$orderService->login(123);`

**说明**：虽然两个服务都有@login方法，但只匹配UserService对象的调用。

### 案例2：变量类型无法确定的调用
```php
<?php
class UserService {
    /**
     * 用户登录
     * @core login
     */
    public function login($username, $password) {
        // 登录逻辑
    }
}

class Controller {
    public function handle($service) {
        // $service 参数类型未知
        $service->login('user', 'pass'); // <- 不会被找到
    }

    public function handleWithCast($data) {
        $service = (UserService) $data; // 类型转换，但PHP中类型无法静态确定
        $service->login('user', 'pass'); // <- 不会被找到
    }
}
```

**搜索结果**：无结果

**说明**：如果调用对象的类型无法在静态分析中确定，则不会被匹配。

### 案例3：不同命名空间但类名相同的调用
```php
<?php
namespace App\Service;

class UserService {
    /**
     * 用户登录
     * @core login
     */
    public function login($username, $password) {
        // 登录逻辑
    }
}

namespace App\Controller;

class SomeController {
    public function handle() {
        $service = new \App\Service\UserService();
        $service->login('user', 'pass'); // <- 会被找到

        // 假设有另一个同名类
        $otherService = new \Other\Package\UserService();
        $otherService->login('user', 'pass'); // <- 如果该类也继承自App\Service\UserService，则会被找到
    }
}
```

**搜索结果**：
- 显示位置：`SomeController::handle` 中的 `$service->login('user', 'pass');`
- 可能显示：`$otherService->login('user', 'pass');`（取决于继承关系）

**说明**：系统会检查类的完全限定名(FQN)和继承关系，相同类名但不同命名空间的类会被分别处理。

### 案例4：复杂表达式中的调用
```php
<?php
class UserService {
    /**
     * 用户登录
     * @core login
     */
    public function login($username, $password) {
        // 登录逻辑
    }
}

class Controller {
    public function handle() {
        // 方法链调用
        $result = $this->getService()->login('user', 'pass'); // <- 可能不会被找到

        // 数组访问
        $services[0]->login('user', 'pass'); // <- 不会被找到

        // 条件表达式
        ($userId ? $this->userService : $this->guestService)->login('user', 'pass'); // <- 不会被找到
    }

    private function getService() {
        return new UserService();
    }
}
```

**搜索结果**：无结果或部分结果

**说明**：复杂的表达式和间接调用可能无法被静态类型分析识别，只会匹配简单的对象属性访问和静态调用。

## 搜索逻辑详解

### 方法收集策略
1. **优先级策略**：先从当前类及其继承链收集，避免不必要的全量扫描
2. **全量补充**：仅当当前类/父类未找到时，才进行全项目范围搜索
3. **性能优化**：使用StubIndex进行高效的索引查找

### 类型匹配规则
1. **对象调用**：检查调用对象的PHP类型是否为当前类或其子类
2. **静态调用**：检查调用类名是否匹配当前类或其子类
3. **兜底规则**：类名相同也认为相关（处理不同命名空间的同名类）

### 过滤逻辑详解
```kotlin
// 伪代码说明过滤逻辑
fun filterRelatedUsages(usages: List<UsageInfo>, phpClass: PhpClass): List<UsageInfo> {
    return usages.filter { usage ->
        val methodReference = findMethodReference(usage.element)
        if (methodReference == null) return@filter false

        val callerType = getCallerType(methodReference, phpClass)
        return callerType != null // 只有类型匹配时才保留
    }
}
```

## 特殊情况说明

1. **多重继承**：如果类有多个父类，会检查所有继承链
2. **接口实现**：接口方法上的@core注解不会被继承（只检查类继承）
3. **Trait混入**：Trait中的方法如果被类使用，会被当作类自身方法处理
4. **循环引用保护**：在检查继承关系时会检测循环引用，避免无限递归
5. **性能限制**：全项目搜索最多返回300个方法，避免性能问题
