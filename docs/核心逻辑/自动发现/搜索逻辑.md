# 自动发现三级选项搜索规则

## 案例分析

### 正面案例（显示三级选项）

**场景1：类中有匹配的 public 方法**
```
配置规则：["get*", "set*", "is*"]
当前PHP类：
class User {
    public function getName() { ... }
    public function setName($name) { ... }
    public function isActive() { ... }
    public function save() { ... }
}
```
显示结果：三级菜单会显示 "get*", "set*", "is*" 三个选项
原因：类中有 public 方法 getName()、setName()、isActive() 分别匹配这三个规则

**场景2：通配符匹配**
```
配置规则：["handle*"]
当前PHP类：
class EventHandler {
    public function handleUserLogin($user) { ... }
    public function handleUserLogout($user) { ... }
    public function processData($data) { ... }
}
```
显示结果：三级菜单会显示 "handle*" 选项
原因：类中有两个 public 方法 handleUserLogin() 和 handleUserLogout() 都匹配 "handle*" 规则

**场景3：前缀匹配回退**
```
配置规则：["save*"]
当前PHP类：
class UserRepository {
    public function saveUser($user) { ... }
    public function saveOrder($order) { ... }
}
```
显示结果：三级菜单会显示 "save*" 选项
原因：虽然 "save*" 转换为正则 `^save.*$` 也能匹配，但即使正则匹配失败，也会尝试前缀匹配 `startsWith("save")`

**场景4：大小写不敏感匹配**
```
配置规则：["GET*"] （忽略大小写开启）
当前PHP类：
class User {
    public function getName() { ... }
    public function getAge() { ... }
}
```
显示结果：三级菜单会显示 "GET*" 选项
原因：配置中 `caseInsensitive=true`，方法名 getName 和 getAge 匹配 GET* 规则

### 反面案例（不显示三级选项）

**场景1：类中没有匹配的 public 方法**
```
配置规则：["get*", "set*"]
当前PHP类：
class UserService {
    public function save($user) { ... }
    public function delete($user) { ... }
    private function getUserById($id) { ... }
}
```
显示结果：三级菜单为空，只显示"正在加载自动发现..."占位符
原因：虽然有 private 方法 getUserById()，但自动发现只匹配 public 方法

**场景2：规则配置为空**
```
配置规则：[]
当前PHP类：
class User {
    public function getName() { ... }
    public function setName($name) { ... }
}
```
显示结果：三级菜单为空
原因：AutoDiscoverSettings 中 rules 列表为空，没有配置任何规则

**场景3：大小写敏感匹配失败**
```
配置规则：["Get*"] （大小写敏感）
当前PHP类：
class User {
    public function getName() { ... }
    public function getAge() { ... }
}
```
显示结果：三级菜单为空
原因：配置中 `caseInsensitive=false`，方法名是 getName 而不是 GetName，规则不匹配

**场景4：非PHP文件或无PHP类**
```
配置规则：["get*"]
当前文件：user.js 或 style.css 或不含类的PHP文件
```
显示结果：三级菜单为空
原因：当前上下文无法解析到PHP类（文件不是PHP文件或文件中没有PHP类定义）

**场景5：方法名为空或异常**
```
配置规则：["get*"]
当前PHP类：
class User {
    public function get() { ... }  // 方法名正常
    // 某个方法由于PSI解析异常导致 method.name 返回null
}
```
显示结果：异常的方法不参与匹配，但其他正常方法仍可匹配
原因：method.name 为null的方法会被跳过（`method.name ?: continue`）

## 显示规则总结

### 核心条件
自动发现三级选项的显示遵循以下条件：

1. **上下文有效**：当前文件必须是PHP文件且包含至少一个PHP类定义
2. **配置规则存在**：AutoDiscoverSettings 中必须配置有规则列表（rules），且列表不为空
3. **类中有匹配的方法**：当前 PHP 类中至少存在一个 public 方法，其方法名匹配该规则
4. **方法可见性限定**：只有 public 方法参与匹配，private/protected 方法不参与匹配

### 匹配逻辑
1. **通配符转换**：规则中的 `*` 被转换为正则表达式 `.*`
2. **正则表达式构建**：将转换后的字符串构建为完整的正则表达式 `^pattern$`
3. **正则匹配**：使用完整的正则表达式进行精确匹配
4. **前缀回退匹配**：如果规则以 `*` 结尾且正则匹配失败，会尝试前缀匹配（`startsWith`），提供更好的兼容性
5. **大小写处理**：根据 AutoDiscoverSettings.caseInsensitive 设置决定是否忽略大小写
6. **异常处理**：正则匹配过程中的异常会被捕获并跳过该方法的匹配

### 缓存机制
- **缓存键**：使用文件路径（virtualFile.path）作为缓存键
- **版本控制**：使用文件修改时间戳（modificationStamp）作为缓存版本判断
- **缓存命中**：文件内容和时间戳未变更时直接返回缓存结果
- **缓存清理**：配置变更时会清理缓存，确保规则更新后能立即生效

### 显示流程
1. **上下文解析**：解析当前编辑器上下文，获取当前PHP文件和类
2. **配置读取**：从 AutoDiscoverSettings 获取规则列表和大小写设置
3. **规则匹配**：对每个配置规则，检查当前类中是否有匹配的public方法
4. **结果展示**：
   - 有匹配规则时：将匹配的规则作为三级菜单选项显示
   - 无匹配规则时：显示"正在加载自动发现..."占位符，并触发后台加载任务
5. **用户交互**：用户点击三级选项时，执行 `AutoDiscoverPatternSearchAction`，进行具体的搜索操作

### 相关配置项
- **rules**：List<String>，配置的匹配规则列表，默认包含 `["get*", "set*", "is*", "has*", "handle*"]`
- **caseInsensitive**：Boolean，是否忽略大小写匹配，默认值为 `true`
